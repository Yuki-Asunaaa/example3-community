# 例题三：网络社区实验室

## 启动

双击 `启动例题三.command`，然后访问 http://127.0.0.1:8767 。首次安装需要联网。若系统不允许双击，在此目录运行：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m application.server
```

已有环境已安装 igraph 0.11.9。退出终端服务后，本地网页将不可访问。使用 `--port` 更改端口，`--data` 指定另一个同格式 JSON。

## 四个独立模块

| 目录 | 职责 | 不做什么 |
| --- | --- | --- |
| data_processing | 读取 JSON、验证编号与端点、标准化无向边、保留原始关系 | 不判断相似度、不分社区 |
| core | 接收节点编号和边，调用 igraph community_multilevel，返回归属、模块度、层级 | 不读文件、不依赖前端或 API |
| application | 调用数据处理与核心，汇总统计、提供 /api/analysis | 不实现社区检测过程 |
| frontend | 读取 API，D3-force 布局、Canvas 绘图、筛选与详情 | 不计算社区归属 |

算法接口：`core.community.detect(node_ids, edges, seed=42, resolution=1.0)`。
数据接口：`data_processing.loader.normalize(raw)` 与 `load(path)`。
应用接口：`application.service.analyze(path)`。
服务只公开 frontend 目录与结果接口，不直接提供原始文件目录。

## 数据与建模

案例3原始数据位于 data/case3.json。共有2354个节点、5393条原始关系，按无向端点合并为5271条边，122条记录被归并，没有自环。每条计算边的 relations 保留原始方向、类型和记录序号。此数据没有权重，所有连接等权；没有计算所谓“语义相似度”。这些是建模选择，不是数据本身保证的事实。

## 使用

- 社区概览：圆为社区，大小表示节点数，线宽表示跨社区边数。
- 节点网络：圆为节点，大小表示度，颜色表示社区。
- 点击社区列表可聚焦；“查看全部”清除筛选。
- 节点搜索支持编号和类型，搜索结果也可通过键盘进入详情。
- 节点详情显示邻居、跨社区标记和完整原始关系。
- “暂停布局”、缩放、适应画布均只影响显示。
- 下载分析结果包含节点属性和原始关系，仅适合本地学习；本次没有发布到外网。

## 结果与解释

固定 seed=42、resolution=1、igraph 0.11.9，得到27个社区，模块度0.7857258214。连通分量为1；4731条内部边、540条跨社区边，内部占比89.755%。算法返回的三层分别有626、51、27个社区，对应Q为0.3720、0.7652、0.7857。

社区4：182个节点，418条内部边，3条外部边，边界占比3/(2×418+3)=0.36%，结构边界较清晰。

社区15：23个节点，34条内部边，26条外部边，边界占比26/(2×34+26)=27.66%，边界相对模糊。跨社区联系可能来自共享基础设施或其他关系，不能据此断定现实身份。

没有真实社区标签，模块度不能当作准确率。把所有节点放入一个社区也能使跨社区边为0，因此不能仅追求跨社区连接少。Louvain并不保证全局最优；关系权重、随机顺序、分辨率和版本会影响结果。模块度存在小社区可能被合并的局限。

社区编号按规模递减排列，仅为阅读便利。D3坐标与算法归属分离，图形位置不表示相似度或地理位置。
